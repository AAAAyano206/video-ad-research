# H3 汽车广告条件向量编辑

## 目的

评估对同一广告母版直接编辑 H3 条件向量，能否批量改变车色、车型、人物或场景，以及在长广告中能否保证接缝，并测试编辑后的推理是否受益于缓存。

## 方案与流程

1. [H3 运行入口](run_h3.py) 录制母版条件包、初始 latent 和实际音视频噪声，再由独立重放请求生成变体。
2. [方向学习](learn_orthogonal_direction.py) 从供体条件均值差估算属性方向，投影掉已知干扰方向。对母版条件施加编辑，固定实际噪声，并进行强度扫描、6 秒及 15 秒试验。
3. [泛化试验](run_generalization.py) 冻结方向和强度，在性能、家庭、户外三类剧情和三个新 seed 上测试。 [分镜链](run_storyboard.py) 用上一镜头末帧给下一镜头做首帧条件。
4. [细归因](run_fine_attribution.py) 改动单行条件、DiT 层组和采样步数。 [缓存基准](run_content_cache_benchmark.py) 用条件、latent、噪声的完整内容 ID 做别名统一和精确命中检查。

## 结果

| 验证 | 结果 |
| --- | --- |
| 6 秒留出方向 | 红转蓝与跑车转 SUV 均 9/9 命中并保留大体剧情。SUV 仍会丢掉原车色及细节。海岸转雪路 0/9。男性转女性命中 9/9，保留原车和广告动作 0/9。 |
| 30/60 秒分镜 | 四段原生 15 秒镜头组成母版。车色方向可以让各段变蓝，原版首帧条件使后续镜头短暂跳回红色。 |
| 单行与层组归因 | 被消融的 8 个条件行均影响构图或车身细节。DiT 五组消融中有四组严重坍缩。测试未找到可安全独立编辑的条件槽或可直接跳过的层组。 |
| 缓存 | 冷请求 15.315 秒，完整载荷一致的两个热别名请求约 1.03 秒，解码音画一致。编辑条件后为 8.041 秒并正确未命中。 |

证据见 [方向评估](generalization-evaluation.json)、[分镜评估](storyboard-evaluation.json)、[层组和采样评估](fine-attribution-evaluation.json) 和 [缓存评估](cache-evaluation.json)。

## 工程意义

可把方向编辑作为镜头级候选生成方法，并用更严格的车身、机位、场景与部件保留指标筛选。跨镜头依赖需显式继承变体视觉条件。精确内容缓存可用于重复请求，一旦改变条件就需重新采样。具体车辆部件的严格验收由 [H3 × Hypit 车辆实验](../h3-hypit-vehicle-edit-lab/README.md) 接续。

本目录的脚本对应原 ModelArts 部署路径，复跑前需要匹配远端 worker、模型版本、原条件包和 FFmpeg。可直接查看归档的 [60 秒母版](storyboard/story-base-60s.mp4) 与 [蓝车变体](storyboard/story-blue-60s.mp4)。
